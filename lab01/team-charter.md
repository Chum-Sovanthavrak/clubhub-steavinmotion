## Working agreements
1. Effective Communication: All team members must communicate regularly through our agreed communication platform and respond to important messages within 24 hours.
2. Fair Task Distribution: Tasks must be divided fairly according to each member's skills, workload, and availability. Everyone is responsible for completing their assigned tasks.
3. Respecting Deadlines: All members must complete their assigned tasks by the agreed deadlines. If difficulties arise, they must notify the team early so the team can adjust its plan.
4. Version Control and Code Management: All team members must use Git and GitHub to manage the project code. Members should work on their assigned branches, write meaningful commit messages, and avoid committing unfinished or untested code to the main branch.
5. Code Quality and Testing: Every member must test their code before submitting it and follow the team's agreed coding standards. Code should be readable, organized, and properly documented where necessary.
6. Code Reviews: Team members should review one another's code before merging significant changes into the main branch. Feedback must be constructive and focused on improving the software.
7. Accountability and Transparency: Each member must take responsibility for their contributions, report their progress honestly, and inform the team promptly about any blockers or delays.

## Decision rules
- Product questions: Discuss requirements and features as a team. The team lead coordinates the discussion, and the team aims to reach consensus.
- Technical questions: Discuss possible solutions, compare their advantages and disadvantages, and agree on the most suitable approach. Test solutions when necessary.
- Deadlock (no agreement after 48 hours): Hold a team vote. If the vote is tied, the team lead makes the final decision after considering everyone's input.
- Where decisions are recorded: lab01/decisions.md
